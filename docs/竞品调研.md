### 三个结构性判断

1. **功能位没有对手，社区位是零。** 论功能：告警生命周期（初研 16 项缺失）已全部落地，
   覆盖面 = Beszel 的告警层 + Gatus 的拨测层，再叠加这三家都没有的 AI 深挖/根因卡/
   提案审批执行/MCP 只读工具面/堡垒机/多用户 RBAC。但在开源项目的标尺上——
   **1 star vs 91k，无 release，无贡献者**——我们目前是「个人完成的精品工程」，
   还不是「开源项目」。开源项目的分水岭不是功能清单，是别人的部署量与 issue 流。
2. **赛道空位仍在，且比初研时更清晰。** 关键词「monitoring + LLM agent diagnosis」
   搜索结果全是 0–1 star 的玩具仓。大玩家不往下做（Keep/Aurora/kagent 全部瞄准
   企业云/K8s，吃现成监控数据）；轻量玩家不做 AI 深度（Beszel/Gatus 的 release
   全是采集面打磨）；AI 玩家不做采集与轻量部署（Aurora 一个栈要 Memgraph+Weaviate+Vault）。
   「**把诊断-审批-执行闭环装进一台 2GB 内存自托管盒子里**」这个组合依然无人占据。
3. **MCP 与执行审批两条铁律都被赛道验证了。** glances 内置 MCP server、kagent 以
   MCP 为工具层、k8sgpt/holmesgpt 只读诊断——与我们的只读提议制方向一致；
   Aurora 的「修复生成 PR」和 Keep 的「YAML 规则动作」是另外两种执行闸门形态，
   都没有走 agent 自主执行，再次印证审批闸门是行业共识而非我们的保守。

### 对排队清单的竞争性建议

- **最缺的不是技术项，是开源基建**：打 tag 发 release、Docker 一键（Dockerfile/compose.yml
  已就绪）、英文 README、界面截图/GIF、（可选）在线 demo。这一步的成本远低于任何
  一个排队技术项，却是「在开源项目中怎么样」从 1 star 起步的唯一路径。
- 技术排队项按竞争价值排序：**拨测矩阵补宽（ICMP/DoH/SNMP）** > **metrics 降采样**
  （撑长期数据故事）> 二级跳板链（深运维场景，受众窄）。
- 可抄清单新增：Beszel 的 agent 证书校验（TOFU 我们已有，可对齐 HTTPS 校验强度）、
  Gatus 的 PG 性能思路不适用（我们是 SQLite 单机，本来就没这问题）。


## 一句话结论

Hermes Watch 在「诊断深度」（根因卡 + 证据链 + 提案审批执行）上领先全部轻量竞品；
真正成片缺失的是 Uptime Kuma / Gatus 已标准化的**告警生命周期层**——这一层全是
小体量可实现的能力，且不与我们的差异化定位冲突。补齐后可用
「**Gatus 的通知层 + holmesgpt 式诊断深度**」讲故事。

## 二、核心事实（带证据）

- **Uptime Kuma 心跳模型**：`DOWN=0/UP=1/PENDING=2/MAINTENANCE=3`；失败先降级 PENDING
  （maxretries 次），耗尽才 DOWN；只有状态翻转的 "important" 心跳才发通知（天然去重）；
  恢复消息带 `lastDownTime`；持续 DOWN 按 `resendInterval` 周期重发。
  README 宣称 90+ 通知渠道，源码实数 108 个 provider。
- **Netdata 状态机**：CLEAR / WARNING / CRITICAL / UNDEFINED / UNINITIALIZED / REMOVED；
  官方滞后示例：`Triggers at 80, clears at 50, preventing flapping between 50-80`。
- **Gatus 恢复模型**：`failure-threshold`（默认 3）连续失败触发；
  `success-threshold`（默认 2）连续成功 → "marked as resolved"；`send-on-resolved` 开关。
- **Beszel 通知**：Shoutrrr URL schema 单表达式 23 渠道；v0.18-0.19 新增
  systemd 失败服务告警、容器健康告警（通知附日志摘录）、每日免打扰时段（quiet hours）。

## 四、本次顺带修复的正确性问题（真实使用会露馅的）

   真实主机根因只陈述规则事实，提案命令里的 IP/服务名来自该机真实证据

5. **删除主机级联清理** findings/proposals/events/proposal_runs。
6. **启动不再被慢主机阻塞**——首轮巡检后台执行；采集并发化（信号量限流 6）。
7. **CORS 全开中间件移除**（前端走 vite 代理本就同源）。
