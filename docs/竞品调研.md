# 竞品调研：开源同类产品与 Hermes Watch 能力对齐

> 2026-09 调研 · 结论驱动本版本（v0.3）的实现清单：**补齐「告警生命周期层」**
> （自动恢复 / 防抖 / 滞后 / 重发 / 免打扰 / 多渠道通知 / 离线检测）。

## 一句话结论

Hermes Watch 在「诊断深度」（根因卡 + 证据链 + 提案审批执行）上领先全部轻量竞品；
真正成片缺失的是 Uptime Kuma / Gatus 已标准化的**告警生命周期层**——这一层全是
小体量可实现的能力，且不与我们的差异化定位冲突。补齐后可用
「**Gatus 的通知层 + holmesgpt 式诊断深度**」讲故事。

## 二、核心事实（带证据）

- **Uptime Kuma 心跳模型**：`DOWN=0/UP=1/PENDING=2/MAINTENANCE=3`；失败先降级 PENDING
  （maxretries 次），耗尽才 DOWN；只有状态翻转的 "important" 心跳才发通知（天然去重）；
  恢复消息带 `lastDownTime`；持续 DOWN 按 `resendInterval` 周期重发。
  README 宣称 90+ 通知渠道，源码实数 108 个 provider。
- **Netdata 状态机**：CLEAR / WARNING / CRITICAL / UNDEFINED / UNINITIALIZED / REMOVED；
  官方滞后示例：`Triggers at 80, clears at 50, preventing flapping between 50-80`。
- **Gatus 恢复模型**：`failure-threshold`（默认 3）连续失败触发；
  `success-threshold`（默认 2）连续成功 → "marked as resolved"；`send-on-resolved` 开关。
- **Beszel 通知**：Shoutrrr URL schema 单表达式 23 渠道；v0.18-0.19 新增
  systemd 失败服务告警、容器健康告警（通知附日志摘录）、每日免打扰时段（quiet hours）。

## 三、缺失清单与本次落地情况

| # | 缺失能力 | 来源竞品 | 本次落地 |
|---|---|---|---|
| 1 | 告警状态机 + 自动恢复（resolved）+ 恢复通知 | Gatus / Netdata / UK | ✅ `scheduler._check_recovery`：连续 3 轮未再触发 → 自动恢复，事件 + 通知 |
| 2 | 恢复通知带持续时长 | UK `lastDownTime` | ✅ 恢复文案「持续 X 小时 Y 分」 |
| 3 | 连续 N 次防抖（PENDING 层） | Gatus `success-threshold` / UK maxretries | ✅ RECOVER_ROUNDS=3，抖动不打翻告警 |
| 4 | 阈值滞后（触发/恢复双阈值） | Netdata CLEAR 模式 | ✅ `rules.CLEAR_THRESHOLDS`：warn 85 触发 / 80 以下才算解除 |
| 5 | 多通知渠道 | UK 108 渠道 / Beszel Shoutrrr | ✅ 6 渠道（企业微信/钉钉/飞书/Telegram/Server酱/通用），设置页可选 + 测试按钮 |
| 6 | 免打扰时段 | UK 维护窗口 / Beszel quiet hours | ✅ `quiet_hours`（支持跨午夜），只记事件不外呼 |
| 7 | 持续告警周期重发 | UK `resendInterval` | ✅ `notify_resend_min`：crit 持续未恢复按周期提醒 |
| 8 | 主机离线检测 | UK 心跳 / Beszel status | ✅ `last_ok_ts` + 3×巡检周期无采集 → 离线；Fleet 徽标 + 拓扑灰色节点 |
| 9 | systemd 失败服务告警 | Beszel v0.19 | ✅（既有能力，本次证实为竞品验证过的方向） |
| 10 | 通知发送留痕 | UK 通知历史 | ✅ `notify_log` 表：成功/失败/免打扰拦截全留痕，设置页展示最近记录 |
| 11 | LLM 出站脱敏（anonymize） | k8sgpt `--anonymize` | ✅ `ai_anonymize` 开关：主机名/IP/用户名出站前替换占位符，单趟正则防二次脱敏，回答映射回真实名 |
| 12 | 心跳历史条带图（24h 上/下） | UK ping chart | ✅ 主机详情 48 桶巡检心跳带（随时间窗缩放），指标阈值映射 ok/warn/crit |
| 13 | PWA（manifest + SW） | UK / statping-ng | ✅ manifest + service worker（仅生产注册，SW 纯透传不缓存——巡检数据必须强实时） |
| 14 | AI 对话流式输出 | 主流 AI 产品标配 | ✅ `/api/chat/stream` SSE 逐 token，LLM 关闭降级本地摘要（已修复空 API Key 时 Bearer 头导致的 LocalProtocolError） |
| 15 | 公开状态页 / 只读分享 | UK / Gatus | ✅ `/status/{token}` 只读页：健康概览 + 主机状态 + 发现标题，60s 自刷新，可撤销/换新，不含地址与证据 |
| 16 | i18n 骨架 | UK Weblate / Beszel 中文站 | ⏳ 远期：接 i18next，默认 zh |

**刻意不追的**：Netdata 边缘 ML、holmesgpt 100+ toolset、Keep 109 集成、
Portainer/Komodo 部署管理面（定位不同）、statping-ng（半弃维护）。

## 四、本次顺带修复的正确性问题（真实使用会露馅的）

1. **真实主机根因卡不再展示演示编造文案**——`analysis.py` 区分 mock/真实：
   真实主机根因只陈述规则事实，提案命令里的 IP/服务名来自该机真实证据
   （此前会把演示 IP `185.220.101.34` 写进真实提案）。
2. **密钥登录的主机可以执行提案了**——`executor._real_exec` 与采集侧统一走
   本机默认密钥（此前空密码时传空密钥列表，免密主机执行必失败）。
3. **agent push 防 NaN/Inf**——一个坏点不再能污染全部阈值判断与图表。
4. **会话可撤销**——改口令/开关访问控制递增 session_epoch，旧 Cookie 全部立即失效。
5. **删除主机级联清理** findings/proposals/events/proposal_runs。
6. **启动不再被慢主机阻塞**——首轮巡检后台执行；采集并发化（信号量限流 6）。
7. **CORS 全开中间件移除**（前端走 vite 代理本就同源）。
